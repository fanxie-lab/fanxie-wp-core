Reference/Design system

Admin Design System

The complete visual language of the Fanxie WP Core admin SPA: every token, layout rule, and component needed to recreate the same look and feel in another plugin.

The palette and type are derived from fanxielab.com so the plugin inherits the studio identity: brand mint on a warm-neutral canvas, Lexend for display and Inter for UI, light mode only, restrained shadows, and a mint glow reserved for primary emphasis. Everything is a CSS custom property prefixed --fx-*.

How to port this. Copy the token CSS block into your plugin (scoped under your admin mount id), self-host Lexend + Inter, then rebuild components from the specs below. The component CSS in each example is lifted verbatim from the source and is drop-in reusable.
  • FontsLexend (500/600/800 — display & headings) · Inter (400/500/600 — body & UI)
  • Signature color#00e298 brand mint — CTAs, active nav, focus, glow
  • Canvas#f7f7f5 warm off-white · surfaces pure white #ffffff
  • ThemeLight mode only — no dark theme
  • ScopingAll tokens & styles live under #fanxie-wp-core-admin to avoid leaking into WP admin chrome
  • Spacing base4px grid (--fx-space-1 … --fx-space-7)

Color

OKLCH was not used in source; values are literal hex from fanxielab.com's light palette. Status colors are darkened brand hues chosen to pass WCAG AA on white. Body text must hit ≥4.5:1; the muted/dim greys below are for secondary and decorative text only.

Typography

Two families on a contrast axis: Lexend (geometric display) for headings, brand marks, group labels, and primary buttons; Inter (humanist UI sans) for body, controls, and metadata. Both self-hosted via @fontsource (no CDN at runtime). Headings carry -0.01em tracking (module titles -0.015em).

Motion

Two easing tokens, both plain ease. Transitions animate color, background, border, box-shadow, and transform, never layout. Reduced motion is always respected via a global prefers-reduced-motion override that collapses durations to ~0.

  • --fx-transition-fast120ms ease — hovers, focus, toggle thumb, nav links
  • --fx-transition-base200ms ease — toast enter/leave, mobile drawer slide
  • Toast enter/leaveopacity 0→1 + translateY(-4px)→0
  • Reduced motiondurations forced to 0.01ms; scroll-behavior auto

App shell & layout

A two-column CSS grid: a fixed 16rem sidebar and a fluid content column. The sidebar is position: sticky full-height; content is capped at 64rem and padded --fx-space-6. Below 900px the grid collapses to one column and the sidebar becomes an off-canvas drawer toggled by a hamburger.

--fx-sidebar-width 16rem / 256px --fx-max-content-width 64rem content padding --fx-space-6 breakpoint 900px

Implementation guardrails

The conventions that keep this system consistent and wp.org-compliant. Carry these over, not just the colors.

  • Scope everythingTokens + all styles live under one mount id (#fanxie-wp-core-admin) so nothing leaks into WP admin chrome. Components use <style scoped>.
  • Light mode onlyNo dark theme. Don't add prefers-color-scheme palettes.
  • Self-hosted fontsNo CDN at runtime — bundle Lexend + Inter via @fontsource.
  • Focus ring:focus-visible → 2px --fx-color-focus-ring outline, 2px offset. UA ring suppressed on nav; mouse click shows nothing, keyboard shows the mint ring.
  • ContrastBody ≥4.5:1. Use text/text-muted for real copy; text-dim only for captions/decoration. Status colors are pre-darkened for AA on white.
  • Never color-onlyPills/toasts pair color with an icon + SR-only prefix.
  • Native labelsEvery control has a visible <label>; placeholders never substitute.
  • Reduced motionGlobal @media (prefers-reduced-motion: reduce) collapses all durations.
  • SR-only utility.fx-visually-hidden for names assistive tech needs but that shouldn't paint.
  • IconsLucide, tree-shaken imports, stroke-width 1.75, currentColor.
  • No arbitrary valuesCompose from tokens — spacing, radius, type, and color all come from --fx-*.
